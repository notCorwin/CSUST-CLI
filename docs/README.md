## 文档与运行时信息的边界

项目有四种信息源，各自解决不同问题：

1. `csust --help`：当前二进制接受什么命令和参数。
2. `csust services catalog --json`：当前探测到哪些服务入口，以及证据和置信度如何。
3. `docs/`：为什么这样设计、怎样解释结果、什么情况下不能继续，以及如何维护。
4. 代码和测试：具体协议、字段映射和实现行为。

文档不应成为第二份命令解析器或第二份服务注册表。需要长期保留某次探测结果时，应明确标注探测时间和快照性质，而不是写成当前能力承诺。

## 文档维护规则

- 只写稳定的业务语义、决策依据、外部前提和失败处理规则。
- 示例使用占位符，不写真实账号、Token、Cookie、验证码或内部地址。
- 上游页面、端点、字段和服务状态变化时，优先更新 adapter 和 catalog 证据；只有稳定规则变化才更新专题文档。
- 新增一份文档前，先确认现有专题不能承载它；避免把同一条规则复制到多个文件。
