# 服务地图

这不是固定的服务清单，而是帮助使用者从业务意图找到正确服务家族的导航。具体入口、当前可用性和证据以 `csust services catalog --json` 为准；命令语法以 `csust --help` 为准。

## 按业务意图选择

| 想完成的事情 | 优先查看的服务家族 | 关键前置 |
| --- | --- | --- |
| 课表、成绩、考试、选课、培养方案和学籍 | 教务核心 | 教务会话；通常受学期和时间窗口影响 |
| 找回学校账号密码 | 统一认证 | 验证码、短信/邮箱/密保中的一种或多种 |
| VPN 应用、设备、审批、消息和文件 | VPN | VPN 账号；部分动作需要二次认证 |
| 网络教学课程、通知和评价 | 网络教学 / 网关 | VPN 会话或该服务认可的登录状态 |
| 教学质量、听评课和毕业设计入口 | 教学质量 / 网关 | VPN、教师/学生角色和业务权限 |
| eHall 服务目录、消息、邮箱、收藏和服务周期 | eHall | 统一认证或当前门户会话 |
| 办事服务、分类、部门、指南和评价 | 融合服务大厅 | 门户会话；具体业务仍由对应服务处理 |
| 馆藏、借阅、读者权限和借阅规则 | 图书馆馆藏 / OPAC | 图书馆读者会话；馆藏和个人业务是不同上下文 |
| 座位、空间、资源状态和个人预约 | 图书馆个人中心 | 图书馆个人会话；预约需先查可用时间 |
| 远程数据库和公开图书馆服务 | 图书馆公开服务 | 通常只读；访问权限仍由资源方决定 |
| 成绩单、在校证明和文件申请 | 电子证明 | 统一认证；下载/投递是文件业务，不只是链接查询 |
| 校园网账单、详单、设备和套餐 | 校园网络 | 网络服务账号和当前校园网环境 |
| 学生资料、学业、消费、借阅和随手记 | 学生数字档案 | 该系统的 CAS/会话 |
| 收费、奖助、减免、退费、缓交和贷款 | 智慧财务 | 财务服务会话；金额状态以远端为准 |
| 仪器、实验项目和预约 | 实验服务 | 服务账号、角色和实际预约窗口 |
| 学籍/人事档案、附件和证明材料 | 档案服务 | 服务类型、个人身份和文件材料 |
| 诉求、建议、投诉和短信验证 | 教育阳光 | 手机验证；提交结果需要服务端确认 |
| 校园地点、公共点和全景资源 | 校园地图 | 通常只读；地点 ID 属于地图上下文 |
| 招聘、期刊、官网和培训资讯 | 公共内容服务 | 通常无需登录，但内容会随上游更新 |
| OnlineJudge 账户、题目、竞赛和提交 | 竞赛服务 | 独立账号；TFA/验证码可能单独启用 |
| 学院科研、交通管理、工会和继续教育业务 | 独立业务服务 | 以各服务的角色和会话为准 |

## 服务家族之间的依赖

```text
统一认证 / CAS
        ├─ 教务、电子证明、图书馆等个人服务
        └─ eHall / 融合服务大厅
                    └─ 发现具体服务入口

VPN 会话
        └─ 网络教学、教学质量及部分校内网关业务

独立账号
        ├─ OnlineJudge、实验、学院业务、部分档案系统
        └─ 各自保存会话，不与学校统一认证强行合并
```

这张图表达依赖关系，不表达登录成功后的权限继承。门户能打开一个服务链接，只说明入口可达；具体服务是否接受当前身份仍需自己的状态或业务探针确认。

## 入口、能力和权限是三件事

面对一个服务时，按以下顺序判断：

1. **入口存在吗？** 能否访问服务地址或门户链接。
2. **能力可表达吗？** 是否发现可复现的查询、提交或文件协议。
3. **当前身份能使用吗？** 当前账号、角色、网络和业务窗口是否满足条件。

目录可能只证明第一步，也可能证明第二步；第三步必须在实际会话中确认。不要因为目录有一个高置信度条目，就假定任意账号都能调用全部操作。

## 选择服务时的常见误区

- “服务大厅里有入口”不等于“服务大厅负责全部业务”。入口后的服务可能有独立认证和独立结果。
- “同一个学号”不等于“同一个账号”。独立平台可能需要另行注册或使用不同角色。
- “查询到了对象”不等于“可以修改对象”。写权限、资格、时间窗口和审核状态还要单独确认。
- “页面能显示下载按钮”不等于“文件已生成或已保存”。文件申请和文件落盘需要各自的证据。
- “系统返回空列表”不等于“没有数据”。先排除登录页、默认页、筛选条件和解析失败。

## 低置信度和状态入口

某些学校入口在探测时可能不可达、返回默认页、403/5xx 或只有登录页。此类条目仍可出现在目录中，目的是保留探索边界和后续线索；它们不应被写进智能体的自动执行路径。

当目标服务属于这类入口时，正确的结果是明确的状态/不可用说明。只有重新获得协议证据、实现业务映射并通过本地验证后，才提升能力承诺。

## 服务地图的维护

服务地图只在业务分类、依赖关系或调用决策发生稳定变化时更新。以下内容留给运行时目录和 adapter：

- 具体主机、端口、路径和重定向；
- 某次探测的临时状态和响应样本；
- 页面字段、隐藏参数和前端资源细节；
- 完整的子命令和选项列表。
