# CSUST CLI 业务模型

CSUST 的服务由不同部门、不同年代和不同技术栈建设。CLI 的统一目标不是让这些系统看起来完全相同，而是让智能体能够用稳定的业务概念组合它们，同时不丢失服务特有信息。

## 业务边界中的基本概念

| 概念 | 含义 | 使用时的注意事项 |
| --- | --- | --- |
| 服务 | 一个学校业务系统或可独立认证的入口 | 同一账号不代表不同服务共享会话或权限 |
| 业务命令 | 对课程、预约、申请、消息等对象的操作 | 参数应描述业务意图，不描述网页控件 |
| 适配器 | 把某个服务的协议翻译成业务命令的边界 | 页面字段和协议差异应留在这里 |
| 目录条目 | 某次探测发现的入口、能力类别和证据 | 它是证据记录，不是 SLA 或权限授予 |
| 业务对象 | 查询、选择、提交或回读的对象 | 标识通常只在所属服务和上下文中有效 |

## 常见业务对象族

### 身份与会话

身份对象描述当前服务认识的账号、角色和会话状态。登录、二次认证、退出和密码找回是会改变认证状态的流程；它们不应被当作普通的“查询用户信息”。

### 教务与学习

学期、课程、班级、成绩、考试、培养方案、选课和各类申请通常相互关联。学期是重要的查询上下文；课程名称适合展示和筛选，课程编号或服务返回的对象标识才适合后续操作。报名、退选、成绩确认和评价可能受时间窗口、资格和审核状态限制。

### 资源与预约

实验仪器、座位、房间、场地和其他资源通常需要区分“资源目录”“可用时间”“个人已有预约”和“预约操作”。看到资源存在，不等于当前时段可预约；看到提交成功，也不等于个人预约列表已经出现记录。

### 申请与工作流

申请、审批、撤回、驳回、认定和审核历史是有状态的流程。当前状态、历史动作和下一步可能分别来自不同响应；智能体不能用一个展示标签替代完整流程状态。

### 档案、证明与文件

档案卷、附件、成绩单、在校证明和导出文件既包含业务标识，也包含本地文件生命周期。远端文件 ID 不应被当作本地路径；下载完成要以文件写入结果为准，不以“已找到下载入口”为准。

### 财务与记录

收费、奖助、退费、缓交、收入、贷款和业务明细要保留金额、方向、时间和来源。金额展示和远端账务状态是两件事；本地计算不能替代服务端确认。

### 公开内容

公告、新闻、期刊文章、招聘岗位和课程目录主要是只读内容。它们可能来自 HTML 页面或公开 JSON，内容可用性和字段稳定性低于核心交易，但仍应保留来源和发布时间等上下文。

## 统一与保留的边界

适配器在可能时提供统一的业务字段，例如名称、标识、状态、时间、分页和详情入口；同时保留服务特有的原始字段或响应证据。统一字段用于组合，原始字段用于追溯和处理尚未抽象的能力。

不要为了统一而做这些事情：

- 把不同服务的状态字符串强行映射成一个没有依据的枚举。
- 把不同系统中碰巧相同的数字 ID 当成全局 ID。
- 把页面顺序、当前年份或默认学期当成业务事实。
- 把缺少字段解释成空值、把登录页解释成空列表、把失败响应解释成无记录。

## 查询与写入的对象关系

稳定的组合方式通常是：

```text
查询上下文（账号、学期、日期、角色）
  → 获取对象列表和状态
  → 选择本次响应中的对象标识
  → 提交业务动作
  → 读取状态或历史确认变化
```

写操作依赖的标识、资格和时间窗口应尽量来自同一次只读查询。旧命令输出、人工猜测的序号和跨服务复制的 ID 都不能作为可靠目标。

## 时间与状态

学校业务受学期、报名批次、教学周、预约日期和服务开放窗口影响。命令可以接受日期或学期参数，但不能保证某个日期在服务端仍然开放；调用者应先查询当前窗口或状态。

状态字段应同时看当前值、服务端说明、审核历史和可用动作。未知状态不是“失败”，也不是“可以继续”；它表示需要更多只读证据或人工判断。

## 对智能体的最低约定

- 把服务名、业务对象和远端标识分开保存。
- 把原始响应当作特定服务的数据，不跨服务直接复用。
- 把列表查询和写操作分成两个阶段。
- 任何涉及账号、成绩、报名、预约、财务、档案或审批的写操作，都以服务端确认结果为完成条件。
- 当统一字段不足以表达服务差异时，优先保留差异并说明证据，不编造统一含义。
