# 认证、会话与人工续办

CSUST CLI 面对的不是一个统一的登录系统，而是一组认证边界不同的学校服务。认证文档的重点是如何选择和续接正确的身份流程，不是复述某个页面的登录字段。

## 认证形态

项目中常见的认证形态可以按调用策略分为：

| 形态 | 适用场景 | 调用者需要准备 |
| --- | --- | --- |
| 统一认证 / CAS / SSO | 教务、电子证明、图书馆等使用学校统一身份的服务 | 学校账号、密码，以及可能的验证码 |
| 服务本地账号 | 独立平台、实验室、OnlineJudge、业务后台 | 该服务自己的账号、角色和密码 |
| VPN 会话 | 既是独立业务，也是部分内网服务的前置通道 | VPN 账号、会话和可能的二次认证 |
| 动态码 / 短信 / 邮件 / TFA | 登录增强、密码找回或敏感操作 | 当前阶段产生的验证码或一次性密码 |
| 公开访问 | 官网、期刊、招聘、课程目录等公共内容 | 通常不需要登录，但仍受网络和上游可用性影响 |

“能在网页上登录”不等于“能在所有命令中复用这个会话”。服务、角色、Cookie、Token 和会话文件应按实际认证边界处理。

## 会话的生命周期

一次需要登录的任务通常经历：

```text
无会话
  → 登录/恢复会话
  → 身份探针确认
  → 读取或提交业务
  → 会话失效/退出
```

多步认证会在中间插入人工续办：

```text
开始认证 → 获取验证码/动态码 → 提交验证 → 登录确认
                         ↘ pending / next ↗
```

状态探针只回答“当前服务是否接受这个会话”，不能证明账号在另一个服务有权限。

## 凭据提供原则

优先级按“明确、短暂、不会进入历史记录”考虑：

1. 密码和一次性秘密优先使用标准输入。
2. 需要自动化时使用环境变量，并控制执行环境和日志采集范围。
3. `.env` 只适合本地受控使用，必须保持未提交且权限为 `600`。
4. 命令行参数只在没有更合适的方式，或服务要求传递非秘密业务值时使用。

不要把密码、验证码、Token、Cookie、状态文件内容或真实个人资料写进 README、测试 fixture、Issue、PR、shell 历史或任务记录。输出中的服务响应和错误详情也应视为可能包含敏感数据，未经确认不要外传。

## 验证码与待续状态

图形验证码不是可靠的自动化输入。拿不到验证码时，命令应保存图片并返回 `captcha_required`，调用者查看后再补充验证码。调用者不能把图片路径本身当作验证码值。

短信、邮件、密保、TFA 和密码找回通常是一个有阶段的流程：

1. 先发起初始认证或找回请求。
2. 读取返回的 `pending`、`next` 或续办文件信息。
3. 获取当前阶段的验证码/动态码。
4. 使用同一服务、同一账号上下文和正确状态继续。
5. 只有最后的身份探针或服务成功结果确认完成，才把流程标记为成功。

验证码发送成功只证明“发送动作被接受”；它不证明验证码已收到，也不证明登录或密码修改已完成。

## 密码找回的边界

密码找回和密码修改都属于远端写操作，即使第一步只是验证身份，也不应静默完成最终变更。调用者应区分：

- 身份资料校验：确认账号、手机号、邮箱或密保条件。
- 验证码发送：创建下一阶段的外部验证动作。
- 身份验证完成：获得提交新密码的资格，不等于密码已经改变。
- 密码提交：必须显式确认，并等待服务端成功证据。
- 新会话验证：如服务允许，用新凭据或状态探针确认结果。

状态文件是续办上下文，不是长期凭据仓库。它应只在本机受控保存，续办完成或失效后按需要清理；不能跨服务、跨账号或跨流程复用。

## VPN 与网关业务

VPN 相关命令有两层含义：

- VPN 自身的账号、设备、申请、消息和文件业务。
- 为网络教学、教学质量或其他内网入口提供可发现的网关通道。

网关地址、服务前缀和访问权限可能由当前 VPN 会话决定。网关业务失败时，先检查 VPN 会话和服务发现，再判断具体业务 adapter 是否损坏；不要直接把固定内部地址写进公共参数。

## 认证失败的判断

| 现象 | 更可能的含义 | 先做什么 |
| --- | --- | --- |
| `credentials_required` | 调用未提供所需账号或秘密 | 检查标准输入、环境变量和服务账号 |
| `captcha_required` / `captcha_failed` | 验证码缺失或不匹配 | 使用当前图片重新输入，不复用旧验证码 |
| `login_required` | 没有可用会话或会话已失效 | 只为目标服务重新登录 |
| `permission_denied` | 身份有效但角色/权限不足 | 检查服务角色和业务资格 |
| 返回登录页或默认页 | 认证跳转、入口或服务状态异常 | 不把页面当作空业务结果，先做状态检查 |
| `pending` / `next` | 认证流程未结束 | 继续当前阶段，不要重复从头登录 |

重复登录不一定能修复权限问题，还可能覆盖已有会话。只有确认会话失效或流程状态不可续时，才重新开始。

## 退出与本地清理

退出命令处理的是具体服务的会话，不保证撤销学校侧所有登录状态。需要切换账号时，应确认目标服务使用的会话文件和服务角色，避免把旧账号的本地 Cookie 当成新账号会话。

发现认证问题时，反馈应包含服务、认证形态、是否经过 VPN、错误 `code` 和下一步状态；不要提交会话文件、验证码原图或秘密。
